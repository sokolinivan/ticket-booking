# High-Level Design WEB-приложения онлайн реализации и бронирования билетов

Документ сформирован на основе описания бизнес-процесса реализации и бронирования билетов.

## Фаза 1. Проектирование архитектуры и базовой инфраструктуры

### Задача 1.1. Определить архитектуру системы
- Зафиксировать три основные подсистемы:
  - подсистема взаимодействия с клиентом;
  - подсистема пользователя системы;
  - подсистема управления продажами.
- Определить физическое разделение WEB-ресурсов и серверов.
- Определить интерфейсы взаимодействия между подсистемами через интернет-канал.

### Задача 1.2. Спроектировать модель данных
- БД пользователей системы.
- БД логов пользователей системы.
- БД клиентов.
- БД мероприятий.
- БД заказов.
- БД статистики.
- БД справочной информации.
- Определить связи между БД мероприятий, клиентов, заказов и статистики.

### Задача 1.3. Спроектировать хранение истории изменений
- Реализовать принцип отсутствия физического удаления изменяемых данных.
- При изменении данных создавать новую запись/версию.
- Обеспечить возможность отслеживания изменений пользователей.
- Предусмотреть возможность восстановления состояния данных на выбранный момент.

### Задача 1.4. Подготовить инфраструктуру приложения
- Развернуть серверные компоненты.
- Развернуть базы данных.
- Настроить сетевое взаимодействие.
- Настроить конфигурацию окружений.
- Подготовить механизмы журналирования и мониторинга.

## Фаза 2. Реализация безопасности и управления доступом

### Задача 2.1. Реализовать авторизацию пользователей системы
- Хранение учетных записей пользователей.
- Проверка учетных данных.
- Управление пользовательскими сессиями.
- Возможность редактирования пользователем собственных данных.

### Задача 2.2. Реализовать службу открытых сессий
- Контроль уникальности активной сессии пользователя.
- Запрет одновременного входа с одинаковым логином с разных устройств.
- Определение завершения пользовательской сессии.
- Поддержка белых и черных списков IP-адресов.
- Ограничение авторизации по стране.

### Задача 2.3. Реализовать службу ролей пользователей
- Определить роли пользователей системы.
- Определить набор доступных функций для каждой роли.
- Реализовать проверку прав доступа к формам и операциям.
- Предоставить администратору полный доступ к системе.

### Задача 2.4. Реализовать аудит действий
- Фиксировать дату и время авторизации.
- Фиксировать изменения данных.
- Хранить ссылки на измененные данные.
- Фиксировать устройство и адрес устройства.
- Вести учет неуспешных попыток авторизации.
- Блокировать авторизацию на 30 минут после трех неуспешных попыток.
